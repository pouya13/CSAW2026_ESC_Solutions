\section{EEPROM Secrets}\label{section:EEPROMSecrets}

\subsection{The first look}
The firmware's help menu listed a command that dumps the configuration database, together with a hint about how it is protected:

\begin{lstlisting}
  dump_eeprom  - Dump config database (protected by an exclusive key repeating over identity)
\end{lstlisting}

``Exclusive key'' reads as XOR, and ``repeating over identity'' suggests a short key derived from the device's identity, repeated over the whole dump. The \texttt{dump\_eeprom} output looked like this:

\begin{lstlisting}[basicstyle=\ttfamily\scriptsize]
--- EEPROM HEX DUMP ---
0010: F4 B9 78 2E 31 3B FF 81 1A 4C 48 64 A8 F6 2A 4D
0020: 07 02 DE BF 79 29 17 23 EF D6 1A 4C 04 2C DC D4
...
0070: F5 B7 69 38 2D 16 E7 91 4D 4C 48 64 FC AE 21 D5
...
\end{lstlisting}

\subsection{Decrypting the EEPROM}
The device's identity is its MAC address, which \texttt{get\_mac} returned as \texttt{B8:D6:1A:4C:48:64}. XORing the dump with the repeating MAC (script \texttt{xor\_dump.py}) gave a readable table of gateways, each record holding a name and a 3-byte MAC suffix:

\begin{lstlisting}[basicstyle=\ttfamily\scriptsize]
4c 6f 62 62 79 5f 47 57 00 00 00 00 10 20 30 01   Lobby_GW....  0.
4f 66 66 69 63 65 5f 47 57 00 00 00 4c 48 64 02   Office_GW...LHd.
...
4d 61 73 74 65 72 5f 47 57 00 00 00 44 78 3b 99   Master_GW...Dx;.
...
\end{lstlisting}

The interesting entry is \texttt{Master\_GW} with suffix \texttt{44:78:3B} and a trailing byte \texttt{0x99}.

\subsection{Getting access}
Next we looked for where a gateway suffix is actually checked. Dumping the RFID card with \texttt{dump\_card} showed block~5 starting with \texttt{4C4864FF}:

\begin{lstlisting}
{"block":4,"data":"010000004C6F63616C47000000000000"},
{"block":5,"data":"4C4864FF000000000000000000000000"},
\end{lstlisting}

This matched the audit log line exactly: the card stores the last gateway suffix (\texttt{4C:48:64}) followed by the response code \texttt{0xFF} (access denied):

\begin{lstlisting}
[AUDIT] Tap session logged: count=1 (Last visit status : Gateway MAC Suffix: 4C:48:64 Response: 0xFF (Access Denied))
\end{lstlisting}

So we overwrote block~5 with the master gateway record recovered from the EEPROM, suffix \texttt{44783B} plus \texttt{99}, and presented the card:

\begin{lstlisting}
> write_block 5 44783b99
{"event":"write_block","status":"pending","block":5,"timeout_s":15,"msg":"Present card within the timeout"}
RFID Card presented (UID: 4A10F055)
{"event":"write_block","ok":true,"block":5}
[AUDIT] Tap session logged: count=2 (Gateway MAC Suffix: 4C:48:64)
[AUDIT] Session counter updated to 3.
[ACCESS-CTL] Primary gateway authorization verified! Access Granted.
\end{lstlisting}

The flag from the log:

\begin{center}
\fbox{\texttt{esc\_2026\{eeprom\_master\_2fe3088dc9313488\}}}
\end{center}
